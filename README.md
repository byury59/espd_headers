# espd_headers

Утилита для подготовки исходных текстов к программной документации по ЕСПД: вставляет в файлы `.c` и `.h` шапку модуля и шапки функций по шаблонам проекта. Шапки потом использует [espd_parser](../espd_parser) (маркер `Component:`).

Утилита разовая: применяется один раз к проекту, который ещё не оформлен по стандарту. Для пользователя работает так же, как espd_parser, только без режимов.

## Что умеет

- Рекурсивно обходит проект, пропуская папки из `ignore.txt`.
- Вставляет шапку модуля в начало каждого `.c`/`.h` (`{filename}` — имя файла).
- Вставляет шапку функции перед каждым определением функции и заполняет имя, параметры с направлением `in`/`out`/`in/out`, возвращаемое значение и глобальные переменные.
- Не дублирует шапки при повторном запуске.
- Сохраняет кодировку каждого файла (UTF-8, Windows-1251 и др.).
- Перед изменением файлов спрашивает подтверждение.
- Складывает отчёт и журнал каждого запуска в отдельную папку.

Разделы Parameters, Return value и External data заполняются эвристикой и требуют проверки человеком — подробнее в `Инструкция.txt`, раздел 8.

## Быстрый старт

1. Сделайте резервную копию проекта (или убедитесь, что он под git): файлы меняются на месте.
2. Скопируйте комплект (`espd_headers_XXXX.exe`, `templates\`, `ignore.txt`, `Инструкция.txt`) в папку внутри проекта, например `Проект\PD\`.
3. При необходимости поправьте шаблоны в `templates\` и исключения в `ignore.txt`.
4. Запустите exe и подтвердите обработку.
5. Отчёт появится в `PD\Результаты\ДДММГГ-N_ignore\`.

По умолчанию обрабатывается папка на уровень выше программы — весь проект.

## Параметры командной строки

```
espd_headers.exe [--path ПУТЬ] [--out ПАПКА] [--yes]
```

| Параметр | Назначение |
|---|---|
| `-p`, `--path` | обработать только указанную папку (например, часть большого проекта) |
| `-o`, `--out` | куда складывать папки запусков вместо `Результаты` |
| `-y`, `--yes` | не спрашивать подтверждение |
| `-v`, `--version` | версия программы |
| `-h`, `--help` | справка |

Короткая запись тоже работает: `espd_headers.exe <путь> [<папка_результатов>]`.

## Результаты

```
PD\
└── Результаты\
    └── 240926-1_ignore\
        ├── espd_headers_Шапки.txt   отчёт по каждому файлу: кодировка, статус, вставленные шапки функций

```

## Шаблоны

| Файл | Подстановки |
|---|---|
| `templates\header.txt` | `{filename}` |
| `templates\header_func.txt` | `{funcname}`, `{PARAMS}`, `{RETURN}`, `{EXTERNAL}` |

Защита от дублей шапки функции ищет перед функцией строку `// Name:     <имя>` (см. `FUNC_HEADER_MARKER` в `config.py`).

## Запуск из исходников

Нужен Python 3.8 или новее.

```
python -m pip install chardet
python src\main.py --path <папка>
```

При запуске из исходников программой считается папка `src`: шаблоны и `ignore.txt` берутся из `src`, результаты пишутся в `src\Результаты`. Без `--path` обрабатывается корень репозитория, в том числе `TestProject` — его файлы изменятся (восстановить: `git checkout TestProject`).

## Сборка exe

```
python -m pip install chardet pyinstaller
scripts\build_exe.bat
```

Exe собирается в один файл, в имя добавляется версия из `src\espd_headers\__init__.py`. Готовый комплект окажется в `dist\espd_headers_XXXX\`: `espd_headers_XXXX.exe`, `templates\`, `ignore.txt`, `Инструкция.txt`.

```
src\
  main.py                 точка входа
  ignore.txt              исключаемые папки
  templates\              шаблоны шапок: header.txt, header_func.txt
  espd_headers\

    app.py                основной сценарий работы (класс HeadersApp)
    cli.py                параметры командной строки и подтверждение
    config.py             имена файлов, расширения, ключевые слова C, маркер шапки функции
    app_paths.py          папка программы (exe или исходники)
    ignore_config.py      чтение ignore.txt (класс IgnoreConfig)
    scanner.py            обход проекта и поиск файлов (класс ProjectScanner)
    templates.py          чтение шаблонов шапок
    source_file.py        определение кодировки, чтение и запись файла
    lexer.py              затирание комментариев и литералов

    header_injector.py    вставка шапок и защита от дублей
    reports.py            отчёт по файлам
    run_dir.py            папки запусков ДДММГГ-N_ignore
    run_log.py            журнал работы (консоль + файл)
    symbol_table.py       заготовка: таблица глобальных переменных проекта

```

## Проверка

```
scripts\run_checks.bat
```

Программа меняет файлы на месте, поэтому проверка работает на копиях `TestProject` в `checks\`. Каждая копия обрабатывается дважды: второй прогон не должен ничего менять. Проверяются запуск из исходников и из последнего собранного exe, ошибочный путь и отказ от подтверждения. Ничего не спрашивает; полный вывод — в `checks\checks_log.txt`.
