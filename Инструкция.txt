ИНСТРУКЦИЯ ПО РАБОТЕ С ПРОГРАММОЙ espd_headers


1. НАЗНАЧЕНИЕ

espd_headers вставляет в исходные тексты на C шапки по стандарту оформления:
	- шапку модуля – в начало каждого файла .c и .h;
	- шапку функции – перед каждым определением функции.
В шапке функции программа сама заполняет имя функции и разделы Parameters (с направлением
in, out, in/out), Return value и External data. Остальное (назначение, требования, описания
параметров) дописывает человек.

Программа нужна один раз для проекта, который ещё не оформлен по стандарту. Файлы меняются
прямо в проекте, резервные копии программа не делает – перед запуском сделайте копию проекта
или убедитесь, что он под git.


2. СОСТАВ КОМПЛЕКТА

	espd_headers_XXXX.exe – программа, XXXX – номер версии;
	templates\           – шаблоны шапок: header.txt (модуль) и header_func.txt (функция);
	ignore.txt           – список исключаемых папок;
	Инструкция.txt       – этот файл.

Ниже в примерах для краткости программа называется espd_headers.exe.


3. РАЗМЕЩЕНИЕ

Комплект копируется в отдельную папку внутри основного проекта, например PD
(ту же, где лежит espd_parser):

	Проект\
		PD\
			espd_headers_XXXX.exe
			templates\
			ignore.txt
		src\
		include\
		...

По умолчанию программа обрабатывает папку на уровень выше своей, то есть весь проект.
Результаты сохраняются рядом с программой, в папке PD\Результаты.


4. ШАБЛОНЫ ШАПОК

Шаблоны лежат в папке templates, сохраняются в UTF-8.

header.txt – шапка модуля. Вместо {filename} подставляется имя файла.
header_func.txt – шапка функции. Подстановки:
	{funcname}  – имя функции;
	{PARAMS}    – параметры с направлением: in, out или in/out;
	{RETURN}    – возвращаемое значение;
	{EXTERNAL}  – глобальные переменные, к которым обращается функция.

Повторный запуск шапки не дублирует:
	- шапка модуля не вставляется, если файл уже начинается с первой строки шаблона;
	- шапка функции не вставляется, если перед функцией уже есть строка «// Name:     <имя функции>»
	  (ровно в таком виде, как в шаблоне). Если в шаблоне эта строка оформлена иначе, сообщите
	  разработчику – иначе повторный запуск продублирует шапки.


5. НАСТРОЙКА ИСКЛЮЧЕНИЙ

В ignore.txt перечисляются папки, которые не нужно обходить (сборка, служебные папки
систем контроля версий и т.п.):
	- одна папка на строку, указывается только имя папки (например build, а не src\build);
	- папка с таким именем исключается на любом уровне вложенности;
	- комментарии начинаются с // или # – в начале строки или после имени папки.

Файл можно сохранять в UTF-8 или ANSI (Windows-1251).


6. ЗАПУСК

Двойной щелчок по espd_headers.exe. Программа покажет папку проекта и число найденных файлов
.c и .h и спросит подтверждение. После ответа y вставит шапки, после n – ничего не изменит.
В конце окно ждёт нажатия Enter.

Из командной строки:

	espd_headers.exe --path ..\src\drivers   – обработать только указанную папку
	espd_headers.exe --yes                   – без подтверждения
	espd_headers.exe --out D:\Docs           – сохранять результаты в D:\Docs вместо PD\Результаты
	espd_headers.exe --help                  – справка по всем параметрам

Поддерживается и короткая запись: espd_headers.exe <путь> [<папка_результатов>].


7. РЕЗУЛЬТАТЫ

Главный результат – изменённые файлы проекта. Кроме того, каждый запуск создаёт отдельную
папку внутри PD\Результаты:

	Результаты\
		240926-1_ignore\
			espd_headers_Шапки.txt  – отчёт: по каждому файлу кодировка, статус и функции,
			                          перед которыми вставлена шапка;
			espd_headers_run.log    – журнал работы программы.

Имя папки: ДДММГГ-N_ignore, где ДДММГГ – дата запуска, N – номер запуска за этот день.


8. ЧТО ПРОВЕРИТЬ ПОСЛЕ ЗАПУСКА

Разделы Parameters, Return value и External data заполняются автоматически по тексту функции
и могут быть неточными. Просмотрите их и поправьте вручную. Чаще всего ошибки бывают:
	- в External data – туда могут попасть макросы, типы, поля структур и константы;
	- в Return value – указывается, только если функция возвращает одну переменную (return x;);
	- у параметров-указателей, в которые пишут через -> или в другой функции.
Если перед функцией был старый комментарий, он остаётся над новой шапкой – перенесите его
в графу Note. Разделы шапки модуля (INCLUDE FILES, DECLARATIONS OF TYPES и т.д.) вставляются
пустыми, код по ним раскладывается вручную.


9. ВОЗМОЖНЫЕ ПРОБЛЕМЫ

	«Не найдено файлов .c/.h …»
		– проверьте, что программа лежит внутри проекта (или путь --path указан верно)
		  и что нужные папки не попали в ignore.txt.
	«Указанная папка проекта не найдена»
		– путь в --path указан с ошибкой.
	«Не найден шаблон шапки модуля»
		– рядом с программой нет папки templates с файлом header.txt.
	«Шаблон … должен быть сохранён в UTF-8»
		– пересохраните шаблон в кодировке UTF-8.
	«Не удалось сохранить отчёт …» / «Не удалось создать папку результатов»
		– нет прав на запись в папку: укажите папку результатов через --out.
	В файле неправильно отображается русский текст
		– проверьте кодировку файла в отчёте и сообщите разработчику; исходный файл
		  восстановите из резервной копии.


10. ДЛЯ РАЗРАБОТЧИКОВ: ЗАПУСК ИЗ ИСХОДНИКОВ И СБОРКА

Для работы с готовым espd_headers_XXXX.exe ничего устанавливать не нужно.

Нужен Python 3.8 или новее и библиотеки:
	chardet       5.0 и новее   – запасной вариант определения кодировки (необязательна);
	pyinstaller   любая версия  – только для сборки exe.

Установка одной командой:
	python -m pip install chardet pyinstaller

Запуск из исходников (из корня репозитория):
	python src\main.py --path <папка>
Без --path обрабатывается корень репозитория, в том числе TestProject – его файлы изменятся.

Сборка exe:
	scripts\build_exe.bat          – комплект появится в dist\espd_headers_XXXX

Проверка:
	scripts\run_checks.bat         – результат в checks\checks_log.txt
